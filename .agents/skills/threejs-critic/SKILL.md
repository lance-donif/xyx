# Three.js 独立评审

由未参与制作的人或新会话评审。先写清本轮的交付版本、验收范围、对标物、目标设备和事先约定的例外。按交付物选规则，单项结论只覆盖指定范围，整体验收覆盖所有适用项。网页内嵌视频时分别验交互与成片。

开始验收前读[验证规程](../../../docs/verification.md)。优先执行端到端用户路径，按变化补属性或差分测试。采用事先确认的验收基线，候选附带的标准变更须另有负责人授权。测试未执行或执行到中途时，把已到达的步骤和缺失的结果如实写进证据边界。

## 从成品取证

- 打开最终文件或页面，记录可辨识的版本、环境、实际步骤、预期与观察。影片逐帧查看并播放，页面实际操作。取证可用该版本的成品、可追溯的运行记录、事实出处与人审签核。失败保留第一个偏离的步骤和原始读数，重跑时把改动或复现条件一并记录。
- 把上轮报告作为复验索引。新版本按上轮的问题复现路径或时间段重测。发布验收还要从入口走完当前交付的全部范围。每个通过项都要能追溯到本轮交付版本和运行条件。未覆盖的设备、视口或操作记录为待证。
- 做视觉盲评时，将成品静帧与真实参考打乱、隐藏来源，先记判断和最大差距，再揭晓标签。用实物微距对照主体的轮廓、材质、玻璃和光照。每轮只让制作人修最重要的一项，修后换新评审。小部件最多两轮，主视觉最多五轮。普通部件两轮仍弱时建议删减或绕开。
- 逐项注明「实测」「未测」「无人核实」「不适用」及依据。只有范围以外或已约定豁免的项目可标「不适用」。用标明为样例的观测卡演练规则时，结论须注明「仅限样例」。

## 适用规则

| 对象 | 通过条件 | 如何取证 |
| --- | --- | --- |
| 主体构图 | 主体占画幅 60%–85%，相机角度 35°–55°，两个区间均含端点 | 与参考约定同一占幅口径和角度基准。记录尺寸或角度读数。单张图只能支持能从它观察到的项目。 |
| 视觉与光照 | 主体轮廓与实物特写相符，材质有真实层次。主空间明亮、受日光或约定棚灯照明，各镜头色调一致 | 指到具体部位和帧。先检查过暗表面。着色器修后仍有相同轮廓问题，优先改几何。 |
| 影片 | 第零帧已是完成画面，最长连续定格 ≤ 0.30 秒，文字对比度 ≥ 4.5:1。有配乐时切点合拍、乐曲自然落在片尾卡 | 打开各比例交付文件，按显示时间测量定格，在成片字幕及其实际背景上取样，按节拍表核对切点。 |
| 浏览器产品演示 | 每条受验用户操作都触发指定的可见结果。状态文字、选中控件与画面一致。性能按简报约定 | 在每个约定环境实际点击或触摸，分别记录操作、控件状态与画面变化。有可逆操作时切回复核。注明实机或仿真。 |
| 游戏或可漫游空间 | 目标设备帧率 ≥ 60 FPS，**每个**视图耗时 < 12 ms，游玩中着色器编译 0 次，下载量 < 40 MB | 在最终页面从打开走到完成流程。记最低帧率、最慢视图、游玩阶段的编译计数和下载量。帧时间叠层、Performance 和 Network 可作为读数来源，记录设备、路径和采样条件。 |
| 写实与理解 | 盲评者把 20 张自制静帧中的至少 2 张误判为实拍，首次观看者在静音下能说出作品要传达的事 | 20 是自制帧数，另混入真实参考。保留揭晓前的选择及首次观看者的复述。 |
| 声音与声明 | 有配乐的交付须有人试听选曲并签核最终混音。真实产品声明可追溯至事实文件，示例数字和概念作品在画面上明示 | 记录人对交付版本的签核，逐条对照最终画面与事实出处。自动视觉评审不能代签听感。 |
| 交付范围 | 影片的各尺寸 MP4、适用的仅音乐版、联系表和重建命令齐备。交互作品有固定端口、开关清单和走通的成品路径 | 实际打开交付物，记录位置和结果。未完成的次要功能按简报删减，优先保证主视觉或核心流程。 |

### 影片定格怎么计时

暂停在连续静止画面的第一帧，量到下一幅有可见变化的画面开始显示。若一直静止到片尾，量到最后一帧显示结束。压缩噪点等细小像素差异仍视为同一静止画面。

- 已确认恒定帧率时，可以用静止帧数除以实际帧率。例如 30 FPS 的 9 帧正好是 0.30 秒。
- 变帧率、末帧延长或帧间隔不均时，用交付版的逐帧显示时间戳与持续时间，包含静止段最后一帧的完整显示时长。用测出的时长直接判定，报告时再四舍五入。

## 出具结论

按以下顺序给出本轮结论。

1. **否**。成品证据已确认至少一项阻断，即使还有必检项未测。先修影响最大的已知问题，再补测。
2. **否（待证）**。暂无已确认的阻断问题，但有必检项缺少当前版本的证据。说明需补的最少证据。
3. **是**。全部适用必检项均有当前版本的证据且达标。可以同时列出次要问题。

按影响列出最多五项问题，单项验收也保留编号和严重程度。编号项写明证据位置、实际读数或可见差距，以及验收目标。每次只指定一项优先动作。在证据边界里写明仍缺的项目与原因，无问题时省略问题行。

```text
是／否／否（待证）｜〈本轮验收范围〉
证据｜〈版本、环境、实际步骤或测量方法、读数及原始证据位置〉
1. 〈阻断／次要〉｜〈具体差距和目标〉
下一步｜〈一项优先动作〉
证据边界｜〈范围内仍缺的证据，或已全部覆盖〉
```
