# Three.js 制作

你负责把一个作品做完。先弄清观众必须看到或做成的那一件事，再据此取舍。制作人记录实测结果，成品是否达标由独立评审判定。用户只要求策划或演练时，停在约定的交付物，明确哪些动作还待执行。

## 开工与接手

1. 新项目的开工回复恰好三行，依次写「交付物」「必须做到的一件事」「本次舍弃项」。把时间、比例、关卡或房间范围写具体，将核心动作写成观众能看到的结果。
2. 续做项目时，先读最新 `STATUS.md` 和 `DECISIONS.md` 或用户提供的交接记录。接手回复直接给交接进度、已验证的版本与范围、本轮下一步和待复验项。进度有新增成果才更新，上一轮的局部通过保留为历史记录。
3. 从简报摘出交付物、规模、受众与展示设备、对标实物、参考链接、事实文件、品牌素材和预算。逐项确认验收目标与测量条件，记录约定的例外。缺少材料时先推进可逆工作，把依赖它的判断留待验证。
4. 参考素材只供测量。真实产品的性能、规格和比较性主张逐条对应事实文件。移除无依据的真实主张，演示用数字要在画面上标「示例」，概念作品要在画面上标「概念」。
5. 实际制作时维护 `STATUS.md`（完成百分比、每项交付的版本、位置、证据、下一步）和 `DECISIONS.md`（取舍、依据、影响）。每次进度更新给出百分比。多人参与时写明每人的任务、产出与负责文件，灯光、色调映射和后期由同一人统筹。功能开关集中在一个配置文件，通过开关停用功能，密钥从环境变量读取。

安排或执行验收时，先读[验证规程](../../../docs/verification.md)。优先从实际入口端到端跑到可见结果，有边界或不变量时做属性测试，修复、重构和迁移时用相同输入做新旧差分。实际执行后记录版本、操作、环境、结果和证据。策划阶段把计划中的验证标为待执行。

## 按交付物定验收

- **影片**以最终导出和实际播放为验收对象。网页内嵌影片时，影片质量在成片上测，嵌入与播放在网页上验。
- **浏览器产品演示**以用户完整操作为主线。在约定的设备或视口执行「作出操作 → 预期画面变化 → 界面状态与画面一致」。有可逆操作时再切回一次。附上简报约定的性能目标。
- **游戏和可漫游空间**在目标设备跑完整的可玩循环或入口至出口路线，同时采集运行性能。

## 先量，再做

- 从实物或实拍中测出适用的剪辑间隔、运镜速度、太阳角度、字号等，注明单位和取样位置。产品的标志性动作按实拍原帧率逐帧取关键姿态，保留原有运动。依赖日照的镜头先投射光线，记录主空间的直晒和阴影区，再定分镜。
- 首次渲染前给出一页计划，列出镜头节拍、房间或系统，标明删减项。先跑通 **5 秒端到端试片**。影片从渲染、导出走到打开成片播放，交互作品跑通一个短切片，从打开页面到实际操作和可见结果。记录产物和运行条件，完整的操作流程在灰盒阶段跑通。
- 第一小时用灰盒打通全程并测试。短片先出完整粗剪，演示和空间走完点击或漫游流程，游戏跑通一个可玩循环。选最终观众一定会看到的一处做到交付质量，先单独展示，再扩展其余部分。
- 每轮只调整首要差距并在运动中核实效果。小部件最多两轮，核心主视觉最多五轮。子系统两轮仍弱，就换构图、隐藏弱模型、绕开该系统或删掉对应镜头，并记录取舍。

## 按作品选择工艺

| 适用对象 | 具体做法 |
| --- | --- |
| 3D 主体 | 单独出主资产特写，与实物微距裁图比轮廓、表面和玻璃。优先修涂漆感、玩具感、无反射层次的玻璃。主体占画幅 60%–85%，相机角度 35°–55°，避开正俯视。保持与参考一致的测量口径。着色器改过后，新评审仍指出同一造型问题，就改几何。 |
| 灯光 | 主空间以明亮日光直晒开场。画面偏暗时先检查并提亮过黑的表面。各镜头共用一套棚灯或一个太阳和一套色调映射，正式评审前以匿名 A/B 选定。 |
| 影片节奏 | 用一个可暂停、可定位的时间轴，让给定时间点唯一决定状态。一个原因对应一个可见变化。第零帧即为完成画面。从五秒试片的分镜起，整帧连续定格 ≤ 0.30 秒。需要停留看清动作时，安排符合参考的运镜，并按成片显示时间逐帧计时。字幕对实际背景的对比度 ≥ 4.5:1。 |
| 影片导出 | 原生动效沿 Three.js 时间轴直接渲染导出。采用 AI 视频时，先用 Three.js 锁定场景、相机和节奏并录制草片，取一张主帧在保留构图的前提下用图像模型定风格，再把草片和风格帧一起交给视频模型，分别约束运动和外观。工具受限时记录替代方案及其待验效果。 |
| 声音 | 先无声渲染，再离线混音。把三首真实候选曲调到相同响度，配画面由人试听选曲。按节拍网格剪辑，从片尾卡倒推，使乐曲自然结束。记录听审人的选曲与最终混音签核。静音交付按简报注明。 |

## 送审与交付

逐个送审部件，最后送审全片或完整操作流程。给新评审者可打开的成品及版本、设备与操作路径、对标样本、适用规则、可核对的事实或签核、上轮报告和事先约定的豁免项。素材盲评用匿名乱序对照。每轮仅修最大的差距，修后换一位评审用当前成品复验。可在独立会话调用 `$threejs-critic`。缺少独立评审时，交付状态写「待独立评审」。

把失败和复验结果一并留在交付记录。只在验证结论所对应的版本已实际跑过时引用通过。验收规则和预期结果以事先确认的基线为准。同一必检项三轮诊断与修复后仍失败时，按规程交给负责人判断。

- **交付影片时**打开各要求尺寸的最终 MP4，准备仅音乐版（有配乐时）、关键帧联系表和一条可重建的命令。逐个核对首帧、最长定格、文字对比度、节拍和静音可理解性。
- **交付游戏、可漫游空间或交互演示时**打开固定端口的成品页，附功能开关清单，实走交付路径。游戏和可漫游空间在目标设备上验证帧率 ≥ 60 FPS、每个视图 < 12 ms、游玩中着色器编译 0 次、下载量 < 40 MB。
- **有写实目标时**，把 20 张自制静帧混入实拍参考，交由独立评审盲辨，至少 2 张自制帧被当成实拍才达标。请首次观看者静音观看后复述核心动作，记录原话。
- **交付消息应给出**成品完整路径或可访问地址，概要列出已做、已删、实测数字及条件、评审未通过项、未测项和无人核实项。回到最终导出文件或页面逐条核对声明。只有评审确实给出肯定结论时才能转述通过。
